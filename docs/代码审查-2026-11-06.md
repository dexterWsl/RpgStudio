# 代码审查（2026-11-06）

范围：`app/` 全部 55 个 JS 文件 + 前端网页 + 本地版启动器。审查方式：逐文件通读，再用两个真实/构造的 RPG Maker 工程跑无损回归和接口冒烟。
下面「已修复」是本次直接改掉的；「待处理」按严重度排，方便一条条清。

---

## 一、总体评价

代码质量明显高于一般个人项目：

- 分层干净。`handler` 只做组装和分发，`routes/` 按功能切，`core/` 不认识任何具体游戏，`profiles/` 承载游戏约定——加功能不用动主干。
- 写盘有纪律。`store.edit()` 的「读最新 → 改 → 校验 → 备份 → 原子替换」是全项目最关键的抽象，所有写操作都走它，没有散落的 `writeFileSync`。
- 无损是硬约束，而且有回归测试兜底（`test/roundtrip.js` 在 1727 页的真实工程上逐页验证「不改直接保存一字不动」「改一句只动那一句」）。
- 注释解释的是「为什么」，不是「做了什么」，而且写的是人话。

主要的系统性风险集中在两处：**前端的状态/竞态**（未保存内容可能被重绘冲掉）和**多文件写入不是事务**。

## 三、待处理（按严重度）

### A. 前端：未保存内容可能被冲掉（最高优先）

1. **`web/js/event.js` `go()` / `render()`** —— 只有 `hashchange` 会确认 dirty。`render()` 被条件保存、改名、顶栏切进度（`progress.js`）直接调用时不确认，未保存的台词被整页重绘冲掉且无提示。
   → 把确认收进 `render()`；保存后的刷新传 `force`；按 `at` 暂存 textarea 草稿。
2. **`web/js/progress.js` `refreshWorkspace()`** —— 末尾无条件 `drawSide()`，切天 / 切时段 / 点另一个事件都会重建右栏、替换正在编辑的正文，`S.dirty` 还不复位（之后导航会误报「还没保存」）。
   → 重建前检查 dirty；销毁编辑器时清 dirty。
3. **`web/js/event.js` `save()`** —— 请求期间只禁用按钮、不禁用输入框；`await` 回来后 `S.dirty=false` + `render()`，这期间敲的字直接没了。
   → 发送前快照内容，成功后比对，变了就不 render、不落 dirty。
4. **`web/js/scenes.js` 新建场景弹窗** —— 没有草稿保护，Esc / 点遮罩直接关，几十行台词丢失。
   → 拦 `cancel` 与遮罩点击，内容有变化时确认或写 localStorage。

### B. 前端：竞态（同一类，建议一起做「请求序号/取消」）

5. **`web/js/shell.js` `render()`** —— 没有渲染序号。快速点两个地图/事件时两个 view 都在 `await` 后写 `#main`，慢的旧请求覆盖当前页，`viewMap` 还会把全局地图状态设错。
6. **`web/js/progress.js`** —— 事件详情请求回来后只判 `PW.sel.ev`，不判地图；切到另一张地图的同号事件时，旧响应会显示成新事件，保存就写进了错误的地图。
7. **`web/js/event.js`** —— 进度标记请求回来后只判路由名，不判 `map/ev`，同理会把高亮插到别的页面。
8. **`web/js/shell.js` `showRefs()`** —— 右栏引用请求回来不校验当前选中项；先点 A 再点 B 时慢的 A 覆盖 B，已关闭的侧栏也会被重新填上。
9. **`web/js/gallery.js` / `projects.js` 弹窗** —— 按钮没有 pending 锁，连点两次会加两份回想入口 / 建两张地图。

### C. 写盘一致性

10. **`core/store.js` `edit()`** —— 多文件编辑不是事务：先备份再逐个 `write`，第二个文件失败（EBUSY / 磁盘满 / 序列化异常）时第一个已经落盘，于是 `MapInfos.json` 指向不存在的 `MapNNN.json`，或留下孤儿地图文件。`routes/maps.js`、`routes/scenes.js` 都有多文件 `edit`。
    → 全部先写 `.tmp-<随机>`，全部成功再统一 rename；失败删除 tmp，原文件不动。
11. **`core/store.js` `isPretty()`** —— 只用「文件是不是以 `{\n` 开头」判断排版，会把「开头换行、其余一整行」的文件误判成 pretty 并整文件重排（与「保持原排版」的承诺相反）。
    → 用 `rmStringify(JSON.parse(raw)) === raw` 判定，失败才退回启发式。
12. **`routes/scenes.js` `scene/create`** —— 先写 `CommonEvents.json` 提交场景，再校验地图 / 坐标；后一步失败时场景已经写进去了，重试会再建一个。
13. **`handler.js` `saveSettings()`** —— `writeFileSync` 直接覆盖 `settings.json`；`allSettings()` 解析失败时静默返回 `{}`，下一次保存就把所有工程的设置覆盖掉。
    → temp + rename，解析失败要报错。

### D. 资源与配额

14. **`routes/assets.js`** —— `assets/commit`、`assets/file` 用 `readFileSync` 整文件读入内存，而上传上限配到了 8GB，一张大素材就 OOM。
15. **`routes/assets.js` / `core/zip.js`** —— zip 解压只看压缩包体积，不限条目数、单条解压后大小和总解压量，也没有压缩比校验。
16. **`core/gallery.js` `freeSpot()`** —— 最坏情况 O(W·H·max(W,H))，满图大约两千多万次判定，会卡住事件循环。

### E. 一致性与可维护性

17. **`handler.js` `curReq`** —— 模块级全局变量，`canConfigure()` 在 `await` 之后读它，并发请求会互相覆盖（本机版恒为 true，暂时没影响；挂到别的服务上就有）。
18. **上传上限有三套默认值**（`routes/assets.js` 2GB、`core/projects.js` 4GB、`app/start.js` 8GB），建议收敛成一个配置。
19. **`target` / `fileOf` / `locate`** 在 `routes/events.js` 和 `routes/scenes.js` 各写了一套，校验细节已经不一致。
20. **`core/project.js` 读缓存**键是 `mtimeMs:size`，外部工具在同一毫秒内以相同大小改写会命中旧缓存。
21. **`routes/images.js` 的 `post: {}`** 是死路由；多个 route 文件有未使用的导入；`web/js/map.js` 的 `paintSprite` 无人调用；`map.js` 里 `eventGraphic` 与 `people.js` 各存一份取帧逻辑。
22. **`core/store.js` 临时文件名固定** `f + '.tmp-' + pid`，且 rename 前不 fsync；崩溃会留下永久残留的 `.tmp`。
